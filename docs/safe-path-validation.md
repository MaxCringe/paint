# Safe Path Validation: этап 2

## Что исправлено

- Один и тот же список реальных команд исполняется повторно при разных шагах кадров.
  Пересчитывать новую стратегию для каждого FPS недостаточно: старая версия принимала
  реку s=60 → бревно s=69, но возвращала непригодные при нестабильном FPS команды.
- Добавлены варианты двойного прыжка над бревном и объединёнными опасностями.
  Близкие бревно/река и река/бревно/река больше не запрещаются только из-за типа.
- Отложенная команда ждёт допустимого состояния, а не пропадает при прыжке или полёте.
  В свидетельство записываются именно пользовательские нажатия, включая буферизованный
  запрос; выпуск буфера не выдаётся за новое второе нажатие.
- Проверяется минимальная высота на всём swept-интервале контакта и перемещение тела
  между полосами; безопасной конечной точки кадра недостаточно.
- Планирование получает снимок после коллизий и активации предметов текущего кадра.
  Полёт, движение между полосами и движение душ с магнитом используют общие числовые
  функции runtime и валидатора. Настройки способностей и высоты не изменены.

## Физика и реакция

`physicalPossible: true` означает, что найден физический маршрут. `ok: true` дополнительно
требует воспроизводимого исполнения и бюджета распознавания. Отсутствие найденного
маршрута (`null`) не является математическим доказательством невозможности.

Параметры в `RUN_DIRECTOR_CONFIG`: расстояние обнаружения 40 мировых единиц,
распознавание .35 с, запас .12 с, интервал отдельных команд .04 с. Это **начальная
калибровка**, а не доказанные показатели человеческой реакции. Прежнее появление
препятствия в поле зрения учитывается консервативно по максимальной скорости.
Команды до границы обнаружения не получают положительный запас реакции.

Свидетельство содержит `initial`, `sequence`, `actions`, `end`, `metrics`.
`minRecognitionSlack` — запас сверх .35+.12 с; `transitions` — интервалы между
действиями. Альтернативы считаются проверенными только после собственного replay;
для анализа можно вызвать `validateRunRoute(..., {findAlternatives:true})`.

## Награды и безопасная замена

Цепочка и усиление образуют ветвь выбора. При следующей генерации сохраняется её
безопасный выход; игрок не обязан возвращаться к проигнорированным душам.
Модель учитывает реальный момент подбора шляпы/метлы, полёт душ к магниту и
автоматическую активацию ульты. Случайные параметры уже созданных душ берутся
из runtime. Неподтверждённая новая награда откатывается до отрисовки кадра.

При отказе проверяется оставшийся участок, вначале — продолжение ранее предложенных
команд. Для этой проверки зарезервирован отдельный бюджет. Если игрок уже оказался
в непоправимом состоянии, диагностика отмечает `fallbackUnproven`: новых опасностей
не добавляется, но генератор не обещает устранить уже совершённую ошибку игрока.

`diagnostics().stats` разделяет причины отказов опасностей и `reward:*` — отказы
новых наград. Исчерпание поиска не называется доказанной непроходимостью.

## Ограничение стоимости и воспроизведение

На один поиск: до 12 вариантов полос, ограниченная сетка времени и 6000 шагов.
На секцию: до 18000 шагов, включая зарезервированную проверку fallback.
Проверки платков повторяются при изменении участка пути или состояния, а не
безусловно каждый кадр. Внутри поиска не создаются Three.js-объекты.

Минимальные сохранённые сценарии: `tests/fixtures/safe-path-regressions.json`.
Независимый числовой исполнитель находится в `tests/helpers/runner-oracle.js`;
он не импортирует валидатор. Дополнительно `tests/browser/safe-path.spec.js`
исполняет те же нажатия через настоящий `game.js`. В тестовой сборке можно
ускорять воспроизведение, пропуская только отрисовку промежуточных кадров:
ввод, физика, коллизии и предметы остаются настоящими. Это не тест GPU/FPS.

Команды: `npm test`; `npm run build -- --mode test`;
`RUN_DIRECTOR_TESTS=1 npm run test:browser -- tests/browser/safe-path.spec.js`.
После проверки — обычный `npm run build`. Тестовый мост отсутствует в production.
