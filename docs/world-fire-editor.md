# Редактор огня в игровой сцене

## Открытие

Локально: `npm run dev`, затем добавьте к адресу `?worldEditor=1&seed=1337`.
В обычном URL редактор не загружается и DEV-кнопок нет.
Для специальной сборки: `VITE_ENABLE_WORLD_EDITOR=true npm run build`, затем тот же query-параметр.
Обычная production-сборка (`npm run build`) исключает модуль редактора.
Это переключатель рабочего режима, а не механизм авторизации.

Редактор использует настоящую сцену и реальные instanced-модели леса. Забег,
ветер, переработка растений, препятствия и камера игры останавливаются;
редакторская камера и огонь продолжают обновляться. Для удобства добавлены
временное рабочее освещение и настоящая лавовая переправа, не зарегистрированная
в списке игровых препятствий. После закрытия возвращаются исходные свет и туман,
игровая камера, состояние забега и ввод. Демонстрационная переправа убирается.

## Работа

1. Выберите сосну щелчком либо один из шести видов справа. «Другой экземпляр»
   переносит камеру к другой сосне того же вида. Предпросмотр огня показывает
   выбранный вид на всех его экземплярах.
2. «Добавить огонь», затем щелчок по видимой ветви/стволу. Точка берётся из
   пересечения с настоящим треугольником InstancedMesh, не из центра прокси.
3. Щёлкните по маленькой светлой точке очага либо выберите его в списке.
   Перетаскивайте стрелки манипулятора; кнопки переключают перемещение, поворот
   и масштаб. «На поверхность» переносит уже выбранный очаг следующим щелчком
   по поверхности того же дерева. Esc закрывает редактор.
4. Размер, сила и цвет доступны сразу. Скорость, искры, прозрачность, точная
   локальная позиция, поворот и масштаб — в раскрываемом разделе.
5. «Дублировать», «Удалить», «Отменить» / «Повторить» (Ctrl/Cmd+Z,
   Ctrl/Cmd+Shift+Z или Ctrl/Cmd+Y). Перетаскивание и изменение ползунка — одно
   действие истории. «Сбросить вид» тоже можно отменить.
6. «Скопировать настройки» копирует полный JSON. «Экспорт» скачивает файл,
   «Импорт» проверяет его целиком перед заменой. Ошибочный файл не меняет сцену.
   Пресет сохраняется в браузере отдельно от игровых сохранений. При закрытии
   изменения остаются в текущем специальном сеансе; обычный URL их не подключает.

Orbit: ЛКМ вращает, ПКМ перемещает точку наблюдения, колесо приближает.
WASD перемещает камеру, Q/E меняют высоту, Shift ускоряет, F фокусирует объект.
Клавиши полёта работают, когда фокус не в поле ввода или кнопке.
После закрытия редакторские слушатели удаляются и Controls.dispose() вызывается.
Кнопка повторного открытия существует только в специальном сеансе.

На переправе щёлкайте по обожжённой деревянной полосе у лавы. Координаты:
`position = [x, height, outwardOffset]`, `side = -1 | 1`.
`z = center(x) + side * (halfWidth(x) + outwardOffset)`.
Положение ограничено шириной дерева и полосой 0.02…0.39 м от кромки.
Пресет переносится между разными извилистыми переправами без фиксированного z.
Огонь на базальтовых берегах не добавляется.

Панель seed сохраняет пресет и перезагружает сцену. При импорте другого seed
редактор предлагает применить его через эту панель; импорт огня сам по себе не
пересоздаёт лес. Seed воспроизводит виды/шаблоны/размещения леса и форму
демонстрационной переправы. Фауна, вулкан и игровой случайный поток не подменяются.

## Данные и расширение растений

- `FirePreset.js`: версия 1, seed, `plants[species]`, `deck`; максимум 32 очага
  на вид. Очаг содержит стабильный id, локальные position/rotation/scale, size,
  strength, color, speed, sparks, opacity. Импорт отклоняет неизвестные виды,
  бесконечные числа, повторяющиеся id, выход за бюджеты и неверные типы.
- `ForestGenerator` остаётся владельцем instanceMatrix. `resolveInstance(mesh,
  instanceId)` возвращает корневой прокси, plantId, species, template. Это
  сопоставление построено на том же порядке частей, что и загрузка матриц в GPU.
  Оно работает для сосен, папоротников и травы; редактор огня выбирает только сосны.
- `PlantCatalog` хранит виды, веса, шаблоны и фабрики; `PlantRegistry` — типы и
  выбор; `populateForest` — плотность и группы; генератор — размещение и вывод.
  Следующий этап может добавить в пресет версионированные `placementLayers`
  (family/species, seed, область, density, scaleRange, cluster radius/count).
  Генератор должен читать их и пересоздавать соответствующие прокси/батчи.
  Кисти должны записывать эти слои, а не сохранять редактирование instanceMatrix.
- `ForestFireStudio.getPineFireProfile` даёт исходные очаги шести видов;
  `FireStudioFlames` — общий существующий shader/геометрию. `EditableFire`
  расширяет их только для специального режима: одна группа пламени, одна искр,
  ограниченные GPU-буферы. `LavaDeckFire` продолжает обслуживать обычный забег.
  После закрытия авторские батчи применяются к активным горящим деревьям и
  реальным переправам. Без специального URL этот путь не создаётся.

## Проверки

`npm test`, `npm run build`. Браузер обычной сборки: `npm run test:browser`.
Редактор: `VITE_ENABLE_WORLD_EDITOR=true npm run build`, затем
`WORLD_EDITOR_TESTS=1 npm run test:browser` (нужен Chromium Playwright или локальный
конфиг с `executablePath` для системного Chromium).
Обычные тесты редактора намеренно пропускаются без opt-in сборки.
Браузерный тест проверяет WebGL, добавление на поверхность, историю, JSON,
переправу, закрытие/повторное открытие и возвращение игрового управления.
