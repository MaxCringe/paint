## Что устранено в этой итерации
1. Новая модель не находилась автоматически: устаревший адрес `/fiona/rigged-model.fbx` исправлен на настоящий путь `/models/fiona/rigged-model (1) (1).fbx`.
2. Тест раньше требовал отдельные `run-forward.fbx` и `jump.fbx`, которых не было в GitHub. Зависимость от этих Mixamo-файлов убрана.
3. Бег и прыжок прежде не создавались собственным генератором; теперь **все 23** движения входят в один Python/NumPy-набор.
4. Вместо параллельного старого JS-генератора тест использует одну схему: Python keyframes → компактные данные → Three.js quaternion animation clips. Переключение на оригинальную Фиону сохранено.
5. При провале загрузки модели или анимаций обычная игра не должна подменяться недогруженной 3D-Фионой. Ошибка показывается в DEV-меню.

## Риски, которые остались (не исправляли без отдельного согласования)
**P1 — обязательно проверить в браузере перед релизом:**
- Анимация коленей и складок платья на реальной skinning-модели; чисто автоматическими тестами это не определить.
- Совпадение размера, поворота, положения шляпы на кости Head, метлы под телом, расстояний до бревна; визуальные координаты FBX отличаются от старой Фионы.
- Переходы при двойном прыжке, повторном подкате, выходе из метлы/ульты, смерти и воскрешении; физика отдельно от позы.

**P2 — технический долг:**
- `src/game.js` совмещает слишком много ответственности (ввод, физика, генерация, таймеры, рекорды, анимация); это затрудняет изменения, хотя масштабный рефакторинг сейчас рискован.
- Код для прежней Фионы продолжает обновлять повороты скрытых деталей тела во время теста: основную механику сохраняет, но есть ненужная работа процессора.
- Рекорды теста не записываются в localStorage, однако HUD может временно подсвечивать «новый рекорд» тестового забега — стоит разделить режимы.
- Текстура дороги загружается с `raw.githubusercontent.com`, один SFX — с `assets.mixkit.co`; игра зависит от внешних сайтов.
- Крупные модули `src/obstacles/LavaRiver.js` и `src/world/World.js` нуждаются в отдельном профилировании.
- Нет автоматического полноценного браузерного WebGL-теста и проверок памяти при многократном рестарте.

**P3 — порядок в проекте:**
- Старый просмотрщик `public/fiona-preview.html` и DEV-редактор эффектов — временные инструменты; перед релизом убрать/скрыть.
- Не менять `Stable 1` в `KNOTTY_PINE_RULES.md` до подтверждения владельца.
- **Не удалять** старую `src/player/Fiona.js` и не подменять её без отдельного решения.

## Как проверять после изменений
1. GitHub Actions: `npm test`, `npm run build`.
2. На сайте: обычный забег, затем «ТЕСТ НОВОЙ ФИОНЫ · DEV» без выбора файлов.
3. Бег, прыжок, двойной прыжок, два подката подряд, лужа, метла/бревно, ульта, удар о сосну, смерть, воскрешение.
4. Повторный старт и возвращение к обычной Фионе. Проверка рекордов и FPS.
5. Не считать анимации визуально готовыми, пока владелец не подтвердит внешний вид.

**Где что теперь находится:**

### Оставшиеся ограничения — не путать с исправленными ошибками

1. Визуальное качество походки, одежды, поз и положения шляпы требует пользовательского просмотра: автоматические тесты не способны оценить естественность анимаций.
2. Большой `src/game.js` нельзя безопасно полностью переписать за одну итерацию. Ввод уже вынесен; оставшиеся системы следует выделять по одной с регрессионными тестами.
3. Chromium проверяется на программном WebGL; мобильные GPU, Safari и длительные сессии с мониторингом памяти пока не проходят отдельные автоматические тесты.
4. Текстура дороги и часть звуков остаются на внешних ресурсах по прежней договорённости. Они зависят от доступности этих сайтов.

**Статус:** исправления проверены сборкой и тестами GitHub Actions. Последнюю сборку Vercel нужно сверять отдельно после каждого коммита. Проверка на реальном устройстве остаётся полезной.
